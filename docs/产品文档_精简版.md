# 合肥产业投资推演系统：精简产品文档

> 版本：v1.0（参赛与评审版）  
> 产品名：Make Hefei Great Again  
> 当前状态：后端 MVP 闭环可运行，前端完整接入仍在进行

## 1. 一句话项目简介

让玩家回到 2007—2016 年，在不知道历史结局的情况下扮演合肥市政府，由多 Agent 基于当时可知的真实材料辅助研判产业项目，并通过连续决策与历史回放检验不同投资路径。

## 2. 目标用户与核心问题

### 目标用户

- 直接用户：对公共决策、产业投资和城市发展感兴趣的学生、青年用户与策略模拟玩家。
- 专业用户：需要开展产业案例教学、政府投资培训或决策复盘的教师、研究者与产业从业者。

### 核心问题

重大产业投资并不是简单的“投或不投”。决策者必须在信息不完整、部门目标冲突和财政资源有限的条件下，判断企业能力、技术路线、市场周期与城市产业基础；同时，早期选择还会影响后续财政空间和产业机会。

传统案例复盘已经知道结果，容易产生后见之明；普通大模型回答又难以保证信息时点、预算守恒和证据可追溯。本产品把用户与 AI 一起放回历史发生前，让决策过程成为可以验证、可以解释的实验。

## 3. 方案与赛题的对应关系

本项目以“AI 参与复杂现实决策”为核心落点，把生成式 AI 从一次性问答升级为可协作、可追溯的多智能体系统：

| 赛题关注 | 产品对应方案 |
| --- | --- |
| AI 是否解决真实问题 | 聚焦政府产业投资中的信息不完整、目标冲突和资源竞争 |
| AI 是否承担核心任务 | 四个政府部门 Agent 分别完成财政、产业、技术和发展规划研判，并进行有限质询 |
| 是否具有完整产品流程 | 从历史 Context、企业申请、资金分配到规则结算和终局复盘形成闭环 |
| 是否可信、可解释 | 每条判断关联证据与时间；未来信息隔离；数值结果由确定性规则计算 |
| 是否具备创新性 | 将历史案例做成截止日盲测，并用真实结局检验 AI 当时的判断 |

项目不是用 AI 复述合肥产业史，而是用真实历史建立一个“决策前推演、决策后验证”的实验环境。

## 4. 核心功能与用户流程

### 4.1 核心功能

1. **历史时点冻结**：只展示决策截止日前已经公开的信息，截止日后的年报、项目结果和评级材料仅在终局解锁。
2. **匿名项目竞争**：同一阶段出现 2—3 家匿名企业，共同竞争有限财政点数，避免用户通过企业名称提前知道结局。
3. **多部门研判**：财政、经信、科技、发改四个 Agent 从不同职责出发给出建议、证据、风险和条件。
4. **连续投资决策**：玩家在多家企业间分配财政资源；未获支持的企业也会继续融资、等待、收缩或退出。
5. **规则化状态演化**：规则引擎结算财政余额、企业建设、现金流、产业协同和阶段反馈，早期选择会改变后续局面。
6. **历史回放与解释**：终局揭示企业原型，对照玩家路径、历史决策与真实结果，解释关键分叉和信息盲区。

### 4.2 主流程

```text
进入历史阶段
→ 查看当时可知的城市与产业信息
→ 阅读匿名企业申请及四部门研判
→ 在企业之间分配财政点数
→ AI 生成企业响应，规则引擎统一结算
→ 查看企业、财政与城市变化
→ 进入下一阶段
→ 终局解密并与真实历史对照
```

正式交互保持克制：玩家每阶段仅仅需要调整企业资金分配，并确认一次模拟；部门分析、企业行动、历史事件和状态变化由后台完成，详细证据按需展开。

## 5. AI 承担的关键任务、实现方式与链路

### 5.1 AI 的关键任务

- **部门专业研判**：四个政府部门 Agent 阅读同一份历史事实快照，但依据不同目标、指标和红线独立判断。
- **分歧识别与质询**：编排器识别部门之间真正影响决策的分歧，触发一次定向质询，再整理共识、风险与保留意见。
- **企业自主响应**：企业 Agent 结合自身能力、获得资源、外部事件和既有承诺，选择扩建、研发、融资、争取订单、收缩或等待。
- **解释生成**：AI 将数据和规则结果转换成评委与玩家可理解的决策理由，但不直接生成财政、营收、产能等结算数值。

### 5.2 实现方式

系统采用“AI 负责判断，规则负责结果”的混合架构：

```text
真实历史数据与来源
→ 按截止日过滤的 Context Builder
→ 四部门 Agent 独立初审
→ 冲突识别、有限质询与联席摘要
→ 玩家提交财政分配
→ 企业 Agent 生成行动意向
→ 确定性规则引擎结算
→ 状态快照、证据链与 Historical Replay
```

关键约束包括：

- 数据记录来源、发布日期和可知日期，截止日之后的信息不能进入当期 Context。
- Agent 输出方向、主张、风险、条件和行动意向，不生成最终数值。
- 规则引擎负责财政守恒和状态变化，相同输入与随机种子可复现。
- SQLite 按 `run_id` 保存现实事实、主体判断、承诺与运行日志，支持跨阶段恢复和审计。
- 模型超时、格式错误或断网时使用确定性 fallback，保证演示链路可继续运行。

## 6. 当前完成度与可演示范围

### 已完成

- S1—S4 四阶段确定性投资引擎、滚动财政池和路径依赖结算。
- 合肥 2007—2016 年财政、产业、企业、政策和历史事件数据的 SQLite 存储，以及来源和可知日期管理。
- 截止日过滤、未来信息隔离、Context 构建与证据追溯。
- 四部门初审、分歧识别、一次定向质询、企业行动与联席方案的后端基础闭环。
- 京东方、赛维 LDK 等历史案例回放包；京东方 S1 已建立真实决策基线。
- 企业私有状态、“现实图谱 + 判断账 + 承诺账”持久化，以及基础投后随访。
- HTTP 接口：创建本局、恢复本局、查看研判、提交资金组合和阶段结算。

### 现场可演示

1. 创建一局并进入 2008 年决策时点。
2. 展示截止日过滤，证明 Agent 看不到后来发布的年报和真实结局。
3. 展示匿名企业、四部门不同立场及其证据。
4. 为企业分配财政点数并执行模拟。
5. 展示企业行动、财政守恒和关键状态变化。
6. 通过 CLI/JSON 连续运行 S1—S4，并展示终局历史回放与信息泄漏审计。

### 尚未完成与演示边界

- 前端尚未完整接入，部分能力目前通过后端 API、CLI 和 JSON 展示。
- 多部门链路当前以确定性 fallback 为主，不应宣称已经复原真实政府会议。
- 六个案例的数据深度不同：京东方、赛维 LDK 校准较深，其余案例仍需继续核验和补充。
- 当前结果用于比较决策机制、方向与路径，不用于预测现实项目的精确收益或成功率。
- 风险条款、分期拨付和企业反提案已有后端结构，但在其独立结算效果完成验证前，不作为前端核心操作。

## 7. 创新点

### 7.1 把 Agent 放回历史发生前

系统将“决策时可见信息”和“事后验证信息”隔离。AI 先在不知道结局的条件下判断，终局才解锁真实结果，减少后见之明，也让模型判断能够被历史反证。

### 7.2 AI 与规则引擎分工

AI 负责理解证据、表达立场和模拟主体行动；规则引擎负责预算、建设、现金流与城市状态。这既保留生成式 AI 对复杂材料的理解能力，也避免模型随意编造数值。

### 7.3 多目标冲突而非单 Agent 答案

财政安全、产业落地、技术可行性与长期发展并不存在天然一致的答案。四部门 Agent 让冲突显性化，最终决策仍由玩家完成，AI 是决策协作系统而不是替人拍板的黑箱。

### 7.4 用真实历史验证推演

系统不仅生成一条看似合理的故事，还将推演的方向、时序、机制和信息纪律与真实历史对照。历史成功和失败案例都可以检验系统在当时条件下识别机会与风险的能力。

## 8. 后续延展空间

- **产品化**：完成 Web 前端、阶段结果卡、终局双时间线和证据抽屉，形成可独立体验的四阶段游戏。
- **交互深化**：在规则验证完成后开放分期拨付、里程碑、审计、退出条款和企业反提案。
- **案例扩展**：补齐六个合肥案例，并扩展到其他城市、其他产业和不同历史时期。
- **教学与培训**：生成个人决策报告，用于公共管理、产业经济和投资决策课程。
- **现实决策辅助**：接入新的政策、企业和产业材料，形成不输出单一答案、而是暴露关键假设与风险条件的方案压力测试工具。
- **研究评测**：增加重复运行稳定性、反事实敏感性、Agent 校准度和跨模型对比实验。

## 9. 产品边界

本产品能帮助用户理解复杂决策中的证据、冲突、条件和路径后果，但不提供现实投资建议，不证明因果关系，也不声称精确预测城市或企业未来。财政点数属于场景设定，不等同于真实财政亿元；模拟结论必须与真实来源、假设和限制一起阅读。
