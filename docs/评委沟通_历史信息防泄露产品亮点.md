# 评委沟通：历史信息防泄露为什么是产品亮点

## 一句话开场

> 大多数历史推演是在知道答案后解释历史；我们的系统先冻结当时可知的信息，让 Agent 在不知道结局的条件下决策，最后才揭晓历史结果进行验证。

## 评委真正需要理解的差异

普通历史问答系统把 2008 年发生的事实、2011 年才披露的报告和今天已经知道的项目结果一起交给模型。模型很容易给出流畅而正确的解释，但这不是决策能力，只是后见之明。

我们的系统为每条数据同时记录两个时间：

- `effective_date`：这件事属于哪一年；
- `information_available_date`：当时的人最早什么时候能够知道。

只有满足 `information_available_date <= cutoff_at` 的证据才能进入 Agent Context。后来报告即使披露早年数字，也不能穿越回早期阶段。真实结果则被放在 withheld 区，直到终局 Replay 才揭晓。

## 最有说服力的现场演示

选择 S1 京东方合肥项目，截止日设为 2008-09-12。

第一步，在证据抽屉展示 2007 年财政与产业材料，状态为“当时可知”。

第二步，搜索 2008 年全年财政数据或京东方 2008 年报。界面应显示：

```text
数据所属期：2008 年
材料公开日：2009-03-18 / 2009-04-21
决策截止日：2008-09-12
状态：当时不可知，未进入 Agent Context
```

第三步，让四个部门 Agent 在缺少后来财务结果和项目成败的情况下产生分歧。评委看到的应是财政担心追投，产业部门关注显示产业链，科技部门关注量产可行性，发改部门关注逆周期窗口。

第四步，完成决策后进入终局 Replay，再解锁后来年报、评级材料、建设节点和真实结果，展示“当时判断—后来事实—关键偏差”。

这个四步演示比口头解释更有力量，因为评委能亲眼看到系统拒绝了一条“真实但当时不可知”的数据。

## 90 秒讲解话术

> 我们最担心的不是 Agent 不聪明，而是 Agent 太容易知道答案。历史上的京东方、光伏和半导体项目今天都有大量复盘材料。如果把这些材料全部喂给模型，它一定能讲出一个正确故事，但那不是决策推演。
>
> 所以我们给每条证据设置了两条时间轴：事实发生时间和信息最早公开时间。只有在本轮决策截止日前已经公开的材料，才能进入 Agent 的冻结 Context。比如一份 2011 年报告披露了 2008 年财政数字，这个数字属于 2008 年，但 2008 年的 Agent 看不到它。
>
> 后来的财报、评级报告和真实成败没有被删除，而是进入独立的终局验证区。玩家完成决策后，系统才揭晓这些材料，检查当时的判断是否抓住了正确机制、遗漏了什么，以及哪条新证据会让方案翻转。
>
> 因此，我们不是让 AI 复述合肥为什么成功，而是在没有历史答案的条件下，对政府决策机制做一次可追溯、可证伪的盲测。

## 三分钟答辩结构

1. 痛点：历史案例复盘天然携带后见之明，大模型会把后来结果伪装成当时判断。
2. 设计：双时间字段、截止过滤、冻结 Context、withheld 结果区。
3. 演示：现场展示一条真实数据因发布日期晚于截止日而被拒绝。
4. 验证：终局再解锁同一材料，对照 Agent 原判断。
5. 价值：同一机制可以迁移到产业投资、公共政策、应急决策和战略训练。

## 面对评委追问

### “这不就是数据库加一个日期过滤吗？”

日期过滤仅仅是底层实现。产品价值在于它改变了整个实验协议：Agent 输入、玩家界面、部门争论、派生指标、历史结果和评分全部以同一截止日隔离。系统还会审计每轮引用，任何未来证据都会使该轮失去“可审计运行”资格。

### “你们怎么证明真的没有泄露？”

回答应给出三层证据：数据库查询只选择 `information_available_date <= cutoff_at`；每轮审计记录 `future_evidence_count`；自动测试用后来披露的早期财政数据验证其不会反向进入 S1。同时可以现场打开证据抽屉展示过滤原因。

### “既然隐藏了后来数据，结果会不会不准确？”

决策推演的目标不是用未来信息提高命中率，而是检验在当时信息约束下的判断质量。后来数据仍然用于终局验证，只是不参与前置决策。这反而使结果更接近真实决策环境。

### “和普通情景模拟有什么区别？”

普通情景模拟通常由创作者设定输入和结果。本产品的输入来自可追溯历史来源，信息边界由发布日期机械执行，终局由独立保存的历史材料反证，因此不仅能演示，还能接受审计和复现。

## 不要采用的表达

- 不要只说“我们防止数据泄露”，这容易被理解为网络安全或训练集泄露。
- 不要说“我们的 Agent 能还原历史正确答案”，产品价值恰恰不是答案复刻。
- 不要宣称“完全模拟真实政府”，应表述为“在公开信息边界下检验决策机制”。
- 不要花大量时间讲数据库字段，应先让评委看到一条未来信息被拒绝，再解释技术实现。

## 推荐命名

对外名称优先使用“历史信息盲测”或“截止日冻结推演”。技术文档中继续使用“信息截止与未来信息防泄露”。

推荐主标题：

> 截止日冻结推演：让 Agent 在不知道答案时做决策

推荐副标题：

> 真实历史材料进入同一条证据链，但只有当时已经公开的信息才能影响当时的选择。
