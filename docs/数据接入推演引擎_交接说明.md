> 接手人：后端 / Agent 线同学。
> 数据线（AI 助手）已完成：数据入库、来源溯源（URL/SHA-256）、截止日纪律、案例深校准。剩下的「接线」需要后端配合。

> **✅ 状态更新（2026-08-13，已解决）**：本说明中的两处接线已被后端同学实现，无需再执行。
> ① 母公司财务通过新增 `PARENT_ENTITIES` + `parent_financing_health` 指标接入 `financial_health`（用负债率/利润率等**无量纲比率**跨过美元→亿元口径边界，未做货币换算）。
> ② 多晶硅价格/硅片售价已接入 `supply_pressure`：`max(50 - industry_growth/2, 100 - wafer_asp/2.35*100, 100 - polysilicon_purchase_price/261.8*100)`。

## 一、现状：哪些数据进了推演，哪些没有

所有数据由 `scripts/seed_hefei_database.py` 生成进 SQLite。推演引擎通过
`policytown/investment/context.py` 里的 `COMPANY_ENTITIES` + `_company_derivations`
把观测映射成指标（`financial_health` / `supply_pressure` / `capital_intensity` 等）。

| 数据 | 实体 | 是否进推演 | 原因 |
|---|---|---|---|
| 京东方 2009—2016 财务 | `boe` | ✅ 进 | `company_a` 的 `COMPANY_ENTITIES` 含 `boe` |
| 合肥赛维子公司 2010 财务 | `ldk_hefei` | ✅ 进 | `company_d` 含 `ldk_hefei` |
| 赛维母公司 2008/2009 财务（SEC 20-F） | `ldk` | ❌ 未进 | `company_d` 不含 `ldk` |
| 多晶硅价格 / 硅片售价 / 销量 | `ldk` | ❌ 未进 | `_company_derivations` 不认这些 indicator |

当前 `context.py` 里 `_company_derivations` 只消费这几个 indicator：
`total_investment / assets / liabilities / net_profit / operating_cash_flow / industry_growth`。

## 二、要做的两处接线（都在 `policytown/investment/context.py`）

### 接线 1：让赛维母公司财务驱动 `company_d`

现状：`COMPANY_ENTITIES["company_d"] = {"ldk_hefei", "ind_pv"}`，不含 `ldk`，所以母公司
「高杠杆 + 2009 年净亏 2.34 亿美元」这个赛维失败的核心信号，目前完全没进推演。

⚠️ **单位坑（不能直接加实体就完事）**：母公司财务是**美元（百万美元）**，子公司是**亿元**。
直接把 `ldk` 加进 `COMPANY_ENTITIES`，`_latest` 会把不同口径的资产/负债/净利润混在一起
（例如 -234 百万美元净利 ÷ 19.4 亿元资产 → 比例被 clamp 到 -15），结果反而是错的。

建议二选一（需后端 / Agent 定，因为牵扯企业判断逻辑）：

- **方案 A（推荐）**：给母公司单独建一个「母公司信用 / 再融资能力」指标，例如
  `parent_financing_health`，由母公司负债率（liabilities/assets）+ 净利润方向派生，
  直接喂给赛维的**关键未穿透命题**（「母公司能否在价格下降和高负债下持续提供运营资金、
  采购信用和技术人员」）。这样美元口径单独算，不与子公司亿元口径混合。
- **方案 B**：把母公司美元财务按固定汇率换算成亿元（标注 `assumption`，说明是换算口径），
  与子公司同口径后并入 `financial_health`。

### 接线 2：让价格周期驱动 `supply_pressure`

现状：`supply_pressure` 只由 `industry_growth` 派生，而光伏的 `industry_growth`
（`ind_pv_2016_growth`）要到 2016 年才可见，所以 S1—S3 赛维的供给压力一直是基线值。
多晶硅价格崩盘（$261.8/kg → $86/kg）和硅片售价腰斩（$2.35/W → $1.05/W）这条
「行业周期」证据是死数据。

建议：新增派生 —— 价格越低，供给压力越高（产能过剩）。参考公式：

```python
price = self._latest(context, "wafer_asp", entities)  # 或 polysilicon_purchase_price
if price:
    # 2.35 美元/瓦(2008 高景气) 为基准，1.05(2009 崩盘) 逼近高压力
    result.append(self._derived(
        company_id, "supply_pressure",
        _clamp(100 - float(price.value) / 2.35 * 100),
        "100 - wafer_asp / 2.35 * 100",
        [price],
    ))
```

具体用 `wafer_asp`（硅片售价，直接对应产品端）还是 `polysilicon_purchase_price`
（多晶硅采购价，对应成本端），以及是否需要与现有 `industry_growth` 派生合并取高/取低，
由后端 / Agent 按「哪条更能解释赛维失败」来定。

## 三、接线后的验收

- 赛维（`company_d`）的 `financial_health` 在 S2/S3 随母公司杠杆和亏损下降；
- 赛维的 `supply_pressure` 随多晶硅/硅片价格崩盘而上升；
- 上述每个变化都能回溯到 `observation → source_id → URL → SHA-256`；
- 补一条回归测试：删掉母公司财务或价格观测后，赛维的指标/立场发生可解释变化。

## 四、为什么这件事是卖点

本产品的核心方法论不是「收集了多少数据」，而是：

> 真实历史数据（企业年报、SEC 20-F、统计公报）在「截止日冻结」约束下，经确定性
> Context Builder 映射成指标，驱动部门研判和企业动作，每一步都可回溯到来源哈希。

这条链只有把上述两处接线打通，才能在演示里站得住——否则「真实数据驱动」就只是口头承诺。
