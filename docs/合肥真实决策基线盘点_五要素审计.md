# 合肥真实决策基线盘点（五要素审计）

> 版本：v0.2
>
> 状态：京东方 S1 第一条产品级基线已经落地。用于回答一个前置问题——
>
> > **四个决策阶段（S1—S4）在真实世界是否都对应了政府实际做过、且可核验的动作？**

## 0. 结论先行

**第一条真实决策基线已经完成。** 京东方合肥 6 代线 S1 基线现已固化在
`data/historical_cases/hefei_boe_2008/decision_baseline.yaml`，并由
`policytown/investment/replay_baseline.py` 执行五要素、日期、单位和来源追溯门禁。
Replay 终局会输出动作与时点的结构化对账；现实亿元、持股、协议条件和精确里程碑在当前引擎没有同口径输出，明确标为 `not_evaluable`，不拼成虚假总分。

这里还修正了一处关键泄漏：框架协议虽然在 2008-09-12 签署，但在 2008-09-13 才公开。因此，真实基线可以读取协议，未来截至 2008-09-12 的盲推演 Context 不可读取协议中的动作、175 亿元总投资、90 亿元资本金、60 亿元政府责任及附带条件。

六个案例、四个阶段，政府确实都真实做过动作——「动作」与「时点」两要素基本成立，**推演的前提是成立的**。

真正的问题集中在五要素的后三要素：

1. **「金额·持股」**：政府实际出资 / 股权结构，只有京东方完整。
2. **「条件」**：分期 / 同比例出资 / 里程碑 / 审计 / 退出条款，六个案例全都没有结构化。
3. **「来源」**：鑫昊只有 C 级转载，熔安、北大未名没有可追溯一手来源。

同时，现有 Replay 校准层（`targets.yaml` + `engine._score_replay`）**只有「结果方向」和「投/不投」两个锚，没有「真实政府动作基线」这一层**。这就是为什么需要本盘点，以及为什么要把「真实决策基线」升格为产品级硬门禁。

---

## 1. 五要素标准

一个决策阶段要进入 Replay，必须登记一条「真实决策基线」，五要素齐全 + 来源可追溯：

| 要素 | 含义 | 缺了会怎样 |
|---|---|---|
| 动作 | 政府实际做了什么（投资/追加/配套/重组/退出） | 无从反推，决策点退化为事件 |
| 时点 | 决策发生的具体日期 | 无法做信息截止、无法对齐 Replay |
| 金额·持股 | 政府实际出资额、股权结构 | 反事实没有数值锚 |
| 条件 | 分期/同比例/里程碑/审计/退出条款 | 无法复现"政府为什么这样投" |
| 来源 | 可追溯的一手或高可信公开材料 + 发布日期 | 无从审计，等同编造 |

判定规则：五要素齐 → 可 Replay；只有动作+时点 → 仅可作「方向背景」；只有后验结果、无决策点动作 → 只能进 withheld，不能当基线。

### 3.3 S3 周期分化（2012—2014）—— 最危险阶段

#### 赛维追加 / 重组 —— 方向有、动作无 ❌

方向真实存在：2011-06 多晶硅价格崩（`ldk_poly_price_collapse`，C）→ 2014-10 美国 Chapter 11（`ldk_chapter11_us`，C）→ 2015-11 中国子公司破产（`ldk_bankruptcy_china`，C）。

但合肥政府的**追加 / 重组 / 止损动作 + 金额 + 时点未结构化**，来源仅 C 级 wiki。

#### 北大未名 —— 全缺，S3 反推锚悬空 ❌（`GAP-P2-CASE05`）

`case_status = needs_verification`，缺口：项目名称、项目公司、决策时间、政府参与方式、投资规模、建设进度、经营结果、失败节点与原因。

#### 长鑫存储 —— 只有后验、无决策点动作 ❌

## 4. 结构性缺陷：Replay 基线层缺失

现状（`scripts/export_hefei_case_package.py` 第 64—67 行）：

```yaml
- target_id: historical_outcome   # 结果方向（success/failure）
- target_id: project_action        # 行为（invest）
```

`engine._score_replay` 现有五个维度：direction / sequence / mechanism / path_feedback / leakage。**没有「真实政府动作基线」对照**。

现已在 `targets.yaml` 新增第三种 target，但没有添加会混淆单位的 `action_baseline_score`。Replay 使用独立的结构化 `decision_baselines` 对账结果：

```yaml
- target_id: government_action_baseline
  target_type: action_baseline
  weight: 1.0
  baseline_ref: decision_baseline.yaml
  match_fields:
    - government_action.action
    - decision_date
    - milestones
```

规则：五要素缺失会触发 Pydantic 门禁；来源还必须存在于 SQLite，且有 URL、本地归档和 SHA-256。当前可直接评价动作和阶段时点；财政点数与现实亿元不换算，条件和精确里程碑在引擎未产生同口径输出前均标为 `not_evaluable`。
