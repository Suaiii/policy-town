# 推演沙盘内嵌关系网设计

## 目标

在合肥产业投资决策沙盘中以内嵌视图展示关系网，切换“关系网”标签时不离开当前网页、不跳转到独立应用。最大限度保留原关系网的素白背景、画布、布局、筛选、搜索和时间轴 UI。

沙盘与关系网必须共用 bridge 的事件日志这一套后端事实源。沙盘数据变化后，关系网在激活时及后续更新时反映相应变化。

## 已确认范围

- 图节点仅包含政府与企业。
- 外部环境不作为节点；市场周期、产业冲击、阶段背景和企业自主行动都以相关关系边的注释或标签呈现。
- 不使用 iframe；关系网保留为当前 React 应用内部、可常驻的嵌入组件。
- 不重写原关系网 UI 和交互，只改动宿主集成与数据刷新边界。

## 架构

1. `RelationNetwork` 保持原关系网 HTML、样式和 Cytoscape 脚本的注入式挂载。样式继续限定在 `.rn-app` 作用域，以避免沙盘样式污染素白关系网。
2. 沙盘继续持有交互态；每次产生可观测的业务变化时，将其转换为标准 `SandboxEvent` 并提交至 bridge 的 `POST /api/events`。
3. bridge 的事件存储是唯一持久事实源。`GET /api/events` 提供时间轴；`GET /api/graph` 将事件投影为图快照。
4. 关系网不读取另一个应用、静态 fixture 或沙盘 React 内存状态；它从同一 bridge 获取事件与图快照。
5. 关系网切换为激活状态时调用刷新入口，重新获取日志和最新图快照；事件写入成功后，通过浏览器事件通知已挂载关系网刷新。

## 事件映射

| 沙盘变化 | 事件 / 图变化 | 外部环境注释 |
| --- | --- | --- |
| 接收企业申请 | 政府与目标企业之间建立申请/研判关系 | 当前阶段与市场背景 |
| 政府提交条件单 | 产生或更新投资、产业扶持、行政审批边 | 财政约束、可用资源、支持工具 |
| 企业自主响应 | 更新该企业相关边的状态 | 企业行动与理由 |
| 市场或阶段事件 | 更新受影响关系边的标签或注释 | 例如“信贷与需求转弱” |
| 统一结算与状态变化 | 更新关系强度、标签或可见状态 | 结算结果与产业影响 |

映射逻辑应为纯函数：输入前后沙盘状态及触发动作，输出待写入的 `SandboxEvent[]`。它不接触 React、网络或 DOM，便于单元测试。对同一状态转换不得重复写入等价事件。

## 失败处理

- 写入事件失败不能阻断沙盘的本地交互和状态推进；界面显示同步失败状态，并允许下次动作或显式重试恢复同步。
- 关系网读取失败时保留最近一次可见图，提示数据未同步；不得清空画布。
- 关系网脚本初始化、销毁和刷新必须继续清理动画帧、键盘与窗口监听器，避免切换视图后出现重复监听。

## 验收与测试

1. 单元测试验证沙盘关键动作到事件的映射，以及重复转换的幂等行为。
2. bridge API 测试验证事件写入后 `/api/events` 和 `/api/graph` 返回对应数据。
3. 组件测试验证关系网激活和外部同步通知均会触发刷新。
4. 浏览器验证从沙盘执行条件单、企业响应和结算后，切换关系网可见同一组政府—企业节点与更新边注释。
5. 视觉回归确认关系网保持原本素白背景与控件布局，宿主深色沙盘样式不渗入。

## 非目标

- 不把外部环境建模为独立节点。
- 不迁移或合并另一套关系网应用的前端路由。
- 不重设计关系网 UI、Cytoscape 样式或既有交互。
