# 大厂 Town · 政企互动推演沙盒
### 当前执行方案 v3.1（产品演示优先 · 10 小时可交付版）

> **执行口径**
> - 本文是当前唯一实施依据；v2 仅保留为历史设计参考。
> - 第一优先级是产品体验和 5 分钟演示闭环，其次是机制自洽，实验严谨性不作为本轮主线。
> - 比赛要求纪要仅用于理解方向，不作为逐字验收标准。
> - 所有具体数值都属于虚拟场景中的演示指标，不包装成现实预测。

> v3 相对 v2：**砍掉一半，深化另一半**
> - 场景 9 个 → **3 个**
> - 企业异质性从"参数分布"改为**三厂生命周期**（A 成熟 / B 增长 / C 转型）

> - 补上一个必需角色：**外包服务商**
> - 融入能力边界声明

# 一、一页纸

**世界**：大厂 Town，一座虚拟城市，一个下行周期。

**交互角色**：政府 4 部门 · 大厂 3 家 + 外包商 1 家 · 员工 10 人 = **18 个 agent**

**世界台账**：企业另有公司级人力、招聘、预算和舆情状态。10 名员工是可点击、可访谈的代表角色，不等于企业全部员工，也不用于宣称现实统计精度。

**核心体验**：选一套政策 → 看城市演化 → 中途投放事件 → 点开决策 → 对比另一条世界线 → 自动生成政策简报。

**核心问题**：政府为了稳就业限制大厂裁员，实际会发生什么？

**演示主线**（让用户在操作中看到，不包装成已经证明的现实结论）：

```
① 监管悖论   管 A 裁员 → B 可能也不敢招（预期未来解雇成本）→ 总就业承压
② 结构性错配 A 放出的人，C 接不住 —— 技能不匹配，不是岗位不够
③ 政府内耗   产业部门推 AI 转型 vs 人社部门保就业，同一个政府自己打架
```

**一句话卖点**：在政策发布前，告诉你它会被怎么绕开，代价由谁承担。

# 二、企业系统：三厂 + 一个必需的补充

## 2.1 三家大厂

| | 大厂 A | 大厂 B | 大厂 C |
|---|---|---|---|
| **阶段** | 成熟期 | 高速增长期 | AI 转型期 |
| **处境** | 人员多、业务成熟、人力成本高 | 还在扩张，需要人 | AI 替代部分岗位，同时创造新岗位 |
| **主要动作** | **放人**（渠道选择） | **接人**（招聘节奏） | **换人**（结构调整） |
| **它怕什么** | 舆情、合规成本 | 招错人、未来裁不掉 | 转型失败、新岗位招不到 |
| **政策敏感点** | 裁员门槛与补偿标准 | **未来的解雇成本** ★ | 产业扶持与技能补贴 |

### 为什么这个设计比"6 家参数不同的企业"好

**因为它让代价可见**。原来的设计只能输出"总就业下降了"，现在能展示变化发生在哪个环节：

```
员工状态台账 = 留任 / 转入 B / 转岗 C / 转外包 D / 待业 / 退出劳动力市场
企业经营台账 = 在岗规模 / 招聘名额 / 用工成本 / 技能缺口 / 政策信任
```

企业间转移仅仅改变员工归属；只有进入待业或退出劳动力市场时，才减少世界台账中的就业人数。公司级台账负责数量演化，10 名员工 agent 负责把关键选择讲清楚。

管制收紧后，A 的流出确实变小了（政府 KPI 好看）。但真正的问题在后面两项：
- **B 不敢接**：它预判到未来解雇成本上升，招聘决策变得更不可逆，于是放慢扩张
- **C 接不住**：A 流出的是传统运营、测试、支持岗，C 要的是 AI 相关岗位 —— **技能不匹配**

> **★ 这是 v3 最重要的产品假设**：管制的代价可能不只体现在 A 少裁了多少人，还体现在 **B 不敢接、C 接不住**。
>
> 产品因此提供另一条可操作世界线：**把部分政策资源转向技能转换支持**，让用户直接比较两种政策包的模拟后果。

## 2.2 必须补上的第四个角色：外包服务商 D

**你们的图里缺了它，但没有它整个模型是漏的。**

企业选择“转外包”这个渠道时，人不会凭空消失——他们可能转为外包商员工，待遇和保障状态随之变化，也可能仅仅表现为大厂自有员工数量下降，而不是同口径的正式裁员事件。

外包商 D 的作用：
- **让规避有去处**。没有 D，"转外包"就是个假动作
- **让代价显形**。转岗到 D 的人在统计上"仍在就业"，但实际处境变差了。这正是政策绕开行为最典型的后果
- **它自己也是主体**：承接量受管制影响，可能反而在管制期扩张

D 不需要复杂的决策，动作空间只有两个：接单价格、承接规模。

## 2.3 企业侧为什么只有 4 个 agent

老师明确说过「数量不是评价目标，机制设计才是」。四个主体覆盖了完整的人才循环：**放人 → 接人 → 换人 → 承接**。加到 10 个只会让每个都变模糊。

展示时主动说明这一点，比堆数量更专业。

# 三、政府系统：四部门博弈

## 3.1 四个部门的真实冲突

| 部门 | 它要什么 | 它的动作 | 它跟谁打架 |
|---|---|---|---|
| **人社部门** | 就业稳定、失业率低 | 就业政策、裁员门槛、补偿标准、稳岗补贴 | **产业部门**（AI 转型消灭岗位） |
| **财政部门** | 税收、控制支出 | 补贴额度、税收优惠 | **所有人**（都要钱） |
| **产业部门** | 招商引资、产业升级 | 产业扶持、AI 转型激励 | **人社部门**（要保的岗位正是要淘汰的） |
| **监管部门** | 合规、舆情可控 | 规则约束、执法强度、仲裁便利度 | **产业部门**（管太严企业就走） |

### 最尖锐的那条线

> **产业部门想扶持 C 的 AI 转型（会消灭岗位），人社部门要保住那些岗位。**
>
> 同一个政府，两个部门的 KPI 直接相反。这不是虚构的冲突，是当下真实存在的张力，评委一听就懂。

## 3.2 政策如何产生（这是 v3 最出彩的机制）

**政策不是某个 agent 拍板的，是四部门博弈的产物。**

```
① 各部门独立提案     [4 次 LLM]
   人社：提高程序门槛 + N+3
   财政：补贴总额不超过 X
   产业：不能影响 C 的转型进度
   监管：执法强度提到 0.8

② 联席会议           [1 次 LLM]
   四份提案 + 各自的约束 → 一份综合政策
   输出：最终政策文本 + 妥协记录 ★

③ 政策发布 → 进入企业与市场
```

**「妥协记录」是溯源面板里最好看的东西**：可以直接展示“人社原本要求统一 N+3，产业部门要求给完成转岗培训的企业留出弹性，最终形成 N+2 + 转岗支持”。这就是产品要解决的“你不知道各方为什么这样决策”。

每轮政府侧 5 次 LLM 调用，成本完全可接受。

## 3.3 政企反馈怎么回到下一轮

政企互动不能只停在“政府发政策、企业做反应”。每轮结算后，以下信息进入下一轮联席会：

```
企业动作：正式优化 / 转外包 / 招聘冻结 / 转岗投入 / 迁移意向
市场结果：在岗变化 / 岗位空缺 / 技能缺口 / 财政支出
社会反馈：员工情绪 / 舆情热度 / 申诉数量 / 代表性留言
企业表达：A、B、C 各提交一条政策反馈或诉求
```

四部门只能在预先定义的政策工具箱内调整方案，不能自由编造权限。当前场景统一标注为“虚拟市政策预演”，门槛、补偿和执法强度都是沙盒参数，不冒充现行法律规定。

# 四、员工系统：10 个代表性 agent

## 4.1 分布与流动

```
初始   A厂 4人   B厂 2人   C厂 2人   外包D 1人   待业 1人
                    ↓ 随剧情流动 ↓
出路   留任 / 跳槽B / 转岗C / 转外包D / 失业 / 退出劳动力市场
```

## 4.2 异质性（三个维度就够）

| 维度 | 取值 | 决定什么 |
|---|---|---|
| **储蓄缓冲** | 薄 3 / 中 4 / 厚 3 | 议价能力——撑不住就只能签字 |
| **维权先验** | 低 5 / 高 5 | 敢不敢抗争，决定企业敢用哪些渠道 |
| **技能类型** | 传统 6 / AI 相关 4 ★ | **能不能被 C 接住** |

> 技能类型这一维是 v3 新增的，它是"结构性错配"叙事的载体。若 A 释放的人才以传统技能为主，而 C 的新增岗位要求 AI 技能，市场上就会同时出现**有人待业和岗位空缺**。代表员工负责讲故事，公司级台账负责显示流向。

## 4.3 员工的既要又要

**补偿金最大化 vs 尽快再就业**。拖着不签补偿可能更高，但空窗期变长、错过 B 厂的招聘窗口。

# 五、产品交互与三类场景

## 5.1 用户的完整操作闭环

```
① 选择世界线       无管制 / 稳就业管制 / 技能转换支持
② 点击开始推演     城市地图、时间轴、四方状态同步变化
③ 中途投放事件     只保留 3 张：裁员上热搜 / 仲裁胜诉 / AI 岗位激增
④ 点开任意动作     查看信息来源、目标、决策摘要和后续影响
⑤ 一键生成对比     与另一条世界线并排，并导出一页政策简报
```

演示必须让评委至少完成一次点击或事件投放。仅仅播放动画不算“可干预”。

## 5.2 只保留 3 个场景

v2 列了 9 个场景，砍到 3 个。判断标准：**这个场景不存在，产品主线是否还讲得完整？**

| 场景 | 参与方 | 不可替代性 |
|---|---|---|
| **① 部门联席会** | 政府 4 部门 | 政策的涌现过程，砍掉政策就变成外生脚本 |
| **② HR 谈话间** | 企业 ↔ 员工（一对一） | 渠道选择与议价的实际发生地，三方交互的核心 |
| **③ 社交场** | 员工 ↔ 员工（跨厂） | 信息扩散、维权判例传染、恐慌情绪。优先复用 MiroFish；不可用时降级为规则扩散 |

**人才市场不设为场景**——它是规则结算（匹配函数），不需要 LLM 对话。技能匹配度在这里体现：传统技能的人匹配 C 的新岗位时匹配率极低。

砍掉的 6 个（闭门征求意见、仲裁庭、行业闭门会、信访、招聘市场、企业内部会）全部降级为**规则事件**或直接删除。仲裁在必要时作为社交场里的一条"判例新闻"出现即可。

## 5.3 演示控制

- 播放 / 暂停 / 单步；
- 三张事件卡；
- 任意角色和时间点可点击；
- A/B/C 世界线切换；
- “恢复演示起点”按钮，确保失误后 5 秒内重置。

# 六、单轮时序

```
① 环境更新              景气度、AI 替代进度（外生数组）        [规则]
② 四部门提案            各自基于自己的 KPI                    [LLM ×4]
③ 联席会议              妥协成一份政策 + 妥协记录 ★           [LLM ×1]
④ 企业决策              A 放人 / B 接人 / C 换人 / D 承接      [LLM ×4]
⑤ HR 谈话间             抽样员工与所属企业一对一               [LLM ×3-5]
⑥ 用户干预点            可投事件卡；无操作则继续                [交互]
⑦ 社交场                员工发帖、扩散、情绪传染               [MiroFish/降级规则]
⑧ 人才市场结算          技能匹配、流向分配                     [规则]
⑨ 指标结算              就业、税收、舆情、四部门 KPI           [规则]
⑩ 企业反馈回政府        诉求与结果进入下一轮                    [结构化摘要]
⑪ 快照落库
```

**8 轮**（R1-2 基线，R3 政策出台，R4-8 演化）。
完整运行约 104 次结构化调用。演示不现场等待全部调用：默认播放提前保存的真实运行快照，只现场触发一次角色决策或事件响应。所有快照标注运行时间和场景版本，可随时切回稳定回放。

# 七、产品中的三条世界线

```
A  无管制                        作为对照世界
B  稳就业管制（人社主导）        提高程序门槛与补偿、加强执行
C  技能转换支持（产业主导）★     不限制流动，补贴培训与转岗
```

> **C 世界线是演示反转点**。它直接对应“产业部门 vs 人社部门”的冲突：如果把政策资源从限制流动转向技能转换，城市状态会怎样变化？
>
> 产品展示的是三套政策包的模拟后果，不声称由此证明某个单一政策变量的因果效果。界面使用“模拟方向”和“场景指数”，不显示伪精确现实概率。
>
> 演示希望用户看到：**KPI 好看的方案，未必是整体代价更小的方案。**

时间不够就只展示 A/B。C 只允许使用此前真实保存的运行快照；如果没有可用快照则隐藏入口，不使用未标注 mock 充当结果。

# 八、输出：3 个主视图 + 2 个面板 + 1 份简报

## 8.1 演示主屏

演示不在多个页面之间来回找功能。核心内容放进一张“政策驾驶舱”：

```text
┌ 世界线 A/B/C ─ 播放/暂停/单步 ─ 事件卡 ─ 重置 ─ 生成简报 ┐
│                                                            │
│  大厂 Town 城市地图 / 人才流动              决策溯源面板    │
│  A 放人 · B 接人 · C 换人 · D 承接          当前角色与动作    │
│                                              信息 / 目标 / 摘要 │
│                                                            │
├ 城市决策时间轴：政策 ─ 企业动作 ─ 员工事件 ─ 用户干预 ──────┤
└ KPI 卡片与另一条世界线的差值提示 ───────────────────────────┘
```

点击地图节点、桑基流量或时间轴事件，都打开同一个右侧溯源面板。这样评委不会迷路，讲解者也不用切换多套交互逻辑。

## 8.2 视图清单

| | 视图 | 讲什么 |
|---|---|---|
| **①★** | **人才流动桑基图** | A 流出 → B / C / 外包 D / 失业 / 退出。**主图，一眼看懂** |
| ②★ | **城市决策时间轴** | 政策、企业动作、员工事件和用户干预在同一条线上展开 |
| ③★ | **B 厂招聘曲线**（A/B/C 世界线对照） | 管 A 后为什么 B 也变谨慎 |
| ④ | **四部门 KPI 卡片** | 用并排卡片显示谁获益、谁承担代价，避免雷达图误导 |
| ⑤ | **溯源面板** | 信息来源 + 目标/KPI + 决策摘要 + 动作 JSON + **联席会妥协记录** |
| ⑥★ | **政策简报** | 自动汇总假设、主要变化、绕开路径、受影响群体、局限与下一步 |

**技能错配的呈现**：在桑基图上把“传统技能”和“AI 技能”用两种颜色区分。C 厂的入口仅仅接收满足技能条件的流量，视觉上一目了然。

# 九、用户与边界（浓缩版）

## 9.1 三方价值

| | 一句话 | 具体交付 |
|---|---|---|
| **政府**（主用户） | 政策发布前告诉你它会被怎么绕开 | 漏洞清单、二阶效应提示、方案相对排序 |
| **企业**（次用户） | 同行会怎么动，舆情会怎么烧 | 舆情风险预演、人才窗口时序 |
| **员工**（受益方，非用户） | 不预测你的命运，但让你看清选择的代价 | 处境镜（群体分布，非个人预测） |

政府是主用户，企业是次用户，员工是受益方。对外不再使用“只有一个真正用户”这种容易自相矛盾的说法。

## 9.2 能力边界（独立成页，不要藏）

| ✅ 能做 | ❌ 不能做 |
|---|---|
| 揭示绕开路径的**类型** | 校准的点预测 |
| 二阶效应提示 | 因果证明 |
| 方案**相对排序** | 绝对量级 |
| 群体**分布** | **个体预测** |

**明确拒绝做的功能**：预测个人被裁时点。三个理由——生态谬误、私有信息缺失、这种能力最终会被用来对付员工。

> 展示时说出来：「我们本可以做这个功能，它会很吸睛。我们没做，原因是……」
> **先展示克制，再展示边界。** 顺序反了就像找借口。

## 9.3 可信度分层

```
K1 背景知识       场景参考了什么公开常识或政策讨论；有来源就显示来源
K2 世界规则       哪条状态更新或匹配规则导致了变化；用户可以点开查看
K3 本次运行       当前世界线产生的数值和角色选择；仅代表这一轮模拟
```

本轮演示不把现实校准做成主功能。界面只需要诚实区分“背景知识”“世界规则”“本次运行”，不展示未经来源支撑的现实概率。

# 十、10 小时实施

## 10.1 与 MiroFish 的分工

```
决策层（自己写，约 250 行）
  政府 4 部门 + 联席会议 · 企业 4 家  → 结构化 JSON
            ↓ 动作转新闻      ↑ 舆情/情绪数字
```

# 十一、Demo 脚本（5 分钟）

1. **[0:00-0:20｜20s] 抛问题**
   「政府限制大厂裁员，总就业就一定会变好吗？」让评委先形成直觉。

2. **[0:20-0:55｜35s] 进入产品**
   介绍 A 放人、B 接人、C 换人、D 承接；请评委点击“稳就业管制”并开始推演。

3. **[0:55-1:40｜45s] 看政策如何产生**
   打开联席会妥协记录：人社保就业、财政控预算、产业保转型、监管控舆情。落点是：**「政策不是一个人拍板的。」**

4. **[1:40-2:50｜70s] 亲手干预城市**
   播放到 R4，邀请评委投放“裁员上热搜”事件卡。时间轴立即新增事件，企业与员工状态变化，桑基图中外包和待业流向发生偏移。

5. **[2:50-3:50｜60s] 点开反直觉决策**
   点击 B 厂的“招聘放缓”：展示它当时看到的政策、未来用工成本预期、决策摘要和动作 JSON。随后在世界线对比中看 B 厂招聘曲线。落点是：**「我们管的是 A，影响却传到了 B。」**

6. **[3:50-4:35｜45s] 切换另一条世界线**
   切到技能转换支持，观察传统技能流向 C 的变化。只讲政策包之间的模拟差异，不宣称现实因果或精确预测。

7. **[4:35-5:00｜25s] 交付与收尾**
   点击“生成政策简报”，展示绕开路径、受影响群体、部门分歧与能力边界。收尾：**「在政策发布前，先看看它会被怎样响应，代价会落到谁身上。」**
