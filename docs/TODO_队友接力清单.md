## 2. P0：必须优先完成

### P0-1 冻结政府四部门 Agent 契约

建议负责人：Agent / 后端。

- [ ] 将当前四类专业研判正式命名为财政、经信、科技、发改部门。
- [ ] 定义部门输入：冻结 Context、部门 KPI、红线、可用工具和缺失信息。
- [ ] 定义部门输出：初审立场、主张、证据、置信度、红线和可接受条件。
- [ ] 保留现有确定性研判作为模型失败时的 fallback。
- [ ] 禁止 Agent 直接生成或修改财政点数、企业财务和建设进度。

验收：相同输入和 seed 下结构化输出可复核；所有重要主张绑定 evidence ID 或缺失声明。

### P0-2 冻结企业 Agent 契约与“一图两账”

建议负责人：Agent / 后端。

- [ ] 定义企业固定决策底色：目标、风险偏好、扩张惯性。
- [ ] 实现现实图谱：只读事实、事件、关系、来源和可见时间。
- [ ] 实现判断账：市场、融资、技术执行和政府履约判断。
- [ ] 实现承诺账：政企承诺、到期阶段、触发条件和履约状态。
- [ ] 每个 `run_id` 隔离模拟记忆，不能污染现实证据或其他运行。
- [ ] 为京东方、赛维 LDK、长鑫分别登记一个关键未穿透命题。

验收：任一企业动作能够追溯至事实、判断和承诺；模拟生成的信息不会写回现实来源表。

### P0-3 实现可审计的政企协商最小闭环

建议负责人：Agent / 产品全栈。

- [ ] 根据关键未穿透命题生成核验问题卡。
- [ ] 企业只能以“披露、区间、拒答、交换条件”回应。
- [ ] 将玩家选择转换成结构化政府条件单。
- [ ] 允许企业进行一次结构化反提案。
- [ ] 最终条件写入承诺账，并交给规则引擎结算。
- [ ] 模型超时或 Schema 校验失败时使用确定性默认路径。

验收：完成“核验问题 → 企业回应 → 政府条件 → 企业反提案 → 最终承诺 → 规则结算”全过程，日志可复核。

### P0-4 固化“截止日冻结推演”演示用例

建议负责人：产品 / 测试 / 后端。

- [ ] 固定 S1 京东方演示截止日 `2008-09-12`。
- [ ] 准备一条当时可知证据和两条真实但后来才公开的证据。
- [ ] 输出机器可读的过滤原因：材料公开日、阶段截止日、拒绝原因。
- [ ] 玩家模式只显示“当时不可知”；审计模式显示完整过滤信息。
- [ ] 终局 Replay 再解锁年报、项目节点和真实结果。
- [ ] 增加测试：删除关键证据后，至少一个部门立场或条件合理变化。

验收：现场能够证明系统拒绝一条“真实但当时不可知”的材料，并在终局正确解锁。
