# 前端可视化与交互指导

> 面向：前端产品、UI/UX 与视觉同学。
>
> 本文档只讲**要讲什么故事、有哪些核心原则、产品有哪些硬约束**，不规定具体 UI 形式——呈现方式（卡片、列表、画布、镜头……）由前端同学在原则内自由发挥。
>
> 边界：前端不计算财政点数、Agent 立场、企业反提案、结算结果或评分；这些都来自后端结构化输出。

---

## 0. 视觉定位：坐在合肥政府决策桌前

用户坐在合肥市政府的决策桌前，在不知道历史答案的情况下，听取四部门研判、向企业追问、设定政府条件，然后**看见这个选择如何改变企业、财政和城市**。

新前端已经建立了正确的空间隐喻，这套基底保留：

- **中央 3D 决策桌**：政府决策的主舞台；
- **桌面合肥地图**：政府选择最终落到真实城市空间（这就是"沙盘"）；
- **三家企业席位**：多项目共享同一财政池，存在机会成本；
- **政府席位**：用户是最终决策者，Agent 只提供研判；
- **企业核验镜头**：从宏观资源分配进入一次具体协商；
- **360° 镜头**：用于空间沉浸和演示，不承担关键决策任务。

---

## 1. 决策的两面：对话是"怎么决定的"，沙盘是"决定后发生了什么"

一次决策有两个可视化面，缺一不可：

- **对话（过程）**：四部门怎么开会、政府和企业怎么谈判——回答"为什么这么决定"。
- **沙盘（后果）**：决策桌上的企业项目地块/企业楼长高、亮灯、熄灯，城市车流人流变化——回答"这个决定让世界变成了什么样"。

两面**联动**：对话里政府拍板"投 55 点给某项目"，决策桌上对应项目地块/企业楼就同步扩建、亮灯、车流变密。玩家不只看"说了什么"，更要"看见"决定落到地面上。

---

## 2. 后端已产出两样东西（前端只是"播放"和"呈现"）

### 2.1 已编排好的"对话"

后端 `deliberation.py` 产出结构化完整对话，前端不用自己编：

| 后端结构 | 对话里对应什么 |
|---|---|
| `department_memos`（4 份） | 四个部门各自发言（立场 + 主张 + 证据 + 红线） |
| `meeting.challenges` | 部门质询：A 追问 B，B 回应，立场从 `stance_before` → `stance_after` |
| `meeting.consensus` / `unresolved_disagreements` / `critical_question` | 会议收束：共识、分歧、关键问题 |
| `negotiation_log`（`NegotiationEvent` 序列） | 政企谈判脚本：政府问 → 企业答 → 政府提条件 → 企业反提案 → 政府拍板 → 规则结算 |

### 2.2 已算好的"状态变化"

结算时引擎更新每家企业状态并留下 `StateDelta`（before / delta / after），这就是沙盘的变化来源：

| 后端 `CompanyState` | 含义 |
|---|---|
| `construction_progress`（0—100） | 建设进度 |
| `production_ramp`（0—100） | 投产/爬坡进度 |
| `status` | building / ramping / under_pressure / stalled / exited |
| `financial_health` | 财务健康 |
| `supply_pressure` | 供给压力 |

城市级 `CityMetrics`（`industrial_base` / `supply_chain_strength` / `talent_supply` / `portfolio_public_value`）也随决策变。

---

## 3. Agent 视觉语义（四部门）

Agent 是四个带明确职责和红线的政府视角，用固定颜色区分即可：

| Agent | 固定视觉色 | 用户应看见的核心 |
|---|---|---|
| 财政 | 琥珀 / 金铜 | 当期余量、追加暴露、退出条件 |
| 经信 | 青绿 | 落地能力、供应链、人才与基建 |
| 科技 | 蓝紫 | 技术成熟度、良率、设备与知识产权 |
| 发改 | 暗红 / 砖红 | 产业方向、市场周期、长期布局 |

部门默认只显示「立场 + 一句核心主张 + 置信度」，展开后再给证据、假设、红线、可接受条件。**不要大量拟人化头像、对话气泡或"Agent 思考中"动画**——用户要信任的是判断结构，不是 Agent 的表演。

---

## 4. 三层信息层级

不要一次展开全部 Agent 输出：

- **第一层：现在要做什么**——当前阶段与历史时点、当前流程步骤、焦点企业、本轮可用资源、唯一主操作。
- **第二层：为什么这样建议**——共识、最大分歧、关键未穿透命题、建议方案与少数意见、企业为何接受/反提案/延期/退出。呈现为"争议结构"和"条件差异"，不是聊天记录。
- **第三层：这个判断根据什么**——审计时再展开证据、来源、日期、质量、过滤原因、模型还是 fallback。

---

## 5. 决策流程（主干）

一局沿这条主干走，呈现方式不做限定：

1. **决策时点**：看懂"现在是什么时间、我知道什么、我不知道什么"（阶段日期、截止日、财政池、竞争项目、市场周期、"未来结果已隔离"）。
2. **匿名申请**：在不知道企业真实名称和结果的情况下比较三个项目；焦点在席位/地图/面板间必须同步。
3. **四部门研判**：默认只给联席摘要（共识 / 最大分歧 / 关键未穿透项 / 建议方案 / 少数意见），部门细节按需展开；分歧用「争议结构」表达。
4. **政企协商**：镜头聚焦企业代表，右侧走「关键命题 → 核验问题 → 企业回应 → 政府条件 → 企业反提案 → 确认」这条有限状态机；条件单始终显示"本轮总余额"和"占本轮资源比例"，风险条件分组，结构化选择；反提案要能看清"原条件 vs 反提案"的差异。
5. **企业自主行动**：展示企业"想做什么、为什么"，并明确标注"意图，尚未结算"——不显示数值结果。
6. **统一结算**：结算输入可展开为「上一阶段状态 + 政府条件 + 企业意图 + 历史事件/产业协同 = 下一阶段状态」；用"执行统一结算"，不用"Agent 开始推演"。
7. **状态变化与承诺账**：变化摘要 + 变化因果链（政府条件 → 企业行动 → 规则结算 → 指标变化）+ 承诺账（双方答应了什么、何时到期）；数值用前后对照，色彩按语义判好坏。
8. **终局 Replay**：企业原型解密 + 两条时间线对照（标分叉）+ 两组评价 + 未来证据解封。

---

## 6. 沙盘如何反映决策前后变化（核心）

决策桌面的合肥地图不是静态背景，它是 `CompanyState` / `CityMetrics` / `StateDelta` 的"脸"。

### 6.1 企业项目地块/企业楼的变化

| 后端字段 | 沙盘视觉 |
|---|---|
| `construction_progress` | 建设阶段：地基 → 框架 → 封顶 → 完工 |
| `production_ramp` | 窗户亮灯比例 + 进出车辆 |
| `status = building / ramping / under_pressure / stalled / exited` | 在建脚手架 / 灯火通明 / 部分熄灯+警戒 / 全熄荒废 / 空置暗沉 |
| `financial_health` | 楼体色调：健康偏暖、恶化转灰冷 |
| `supply_pressure` | 项目地块周围拥挤/警戒 |

### 6.2 城市的变化

| 后端字段 | 沙盘视觉 |
|---|---|
| `industrial_base` | 活跃企业地块/楼的数量与规模 |
| `supply_chain_strength` | 车流密度 |
| `talent_supply` | 行人数量 |
| `portfolio_public_value` | 城市整体亮度与繁荣度 |

### 6.3 决策前后的"变化动画"

决策前沙盘停在当前快照；结算后按 `StateDelta`（before → after）播一段短动画——投钱的地块长高、窗户一盏盏亮起、车流变密；被退出/重组的窗户逐盏熄灭、楼体变暗。每个变化可点开看"为什么变成这样"（`reason_code` + 证据）。

---

## 7. 截止日冻结（产品硬约束）

"当时可知 / 当时不可知"是产品最需要被记住的界面特征：

- **玩家模式**：顶部常显"信息截止已生效 · YYYY-MM-DD"；未来材料只显示"当时不可知"，不泄露标题、内容、结果和具体发布日。
- **审计模式**：能说清一条证据为何被拒（事实发生日 → 材料公开日 → 截止日 → 可见/拒绝）；拒绝用封存样式，不是报错红。
- **终局 Replay**：用"解封"动作把后公开材料放回时间线，解封动画只出现一次。

---

## 8. 评价结果显示

分两组，不合成"综合得分"：

- **决策过程评价**（当时决策是否稳健）：关键命题穿透、证据纪律、财政纪律、条件可执行性、组合与公共价值——逐项给，每项带一句"为什么"，不要雷达图。
- **历史校准评价**（这条世界线与真实历史的关系）：方向一致性、顺序合理性、机制证据完整性、路径反馈形成度、信息泄漏审计——显示"哪个决策分叉造成什么后果"，不写成"你猜对了 80%"。

---

## 9. 动效原则

动效用来说明空间和状态，不用来营造"Agent 很忙"。高频操作动效要快、有按压反馈、支持 `prefers-reduced-motion`；结算时先显示计算输入、再让数值一次性刷新；解封这类揭示性动画只出现一次。

---

## 10. 全局交互规则（硬约束）

- **一屏只有一个主操作**：主操作醒目，破坏性操作（退出/拒绝）仅在确有后果时用警示色。
- **视觉状态与后端状态一致**：生成中 / fallback / 无证据 / 截止日后证据 / 结算中 / 成功 / 失败，各有明确且不误导的前端态；失败保留条件单提供重试，不清空用户操作。
- **不做无限对话**：协商是有限状态机 `核验问题 → 企业回应 → 政府条件 → 一次反提案 → 最终确认`，不加自由聊天框、"继续说服企业"、"再问一轮"。
- **证据链可从所有重要结论到达**：部门主张、关键未穿透项、联席建议、企业回应、状态变化、Replay 分叉，点击任意一项都能打开对应证据。

---

## 11. 优先级

- **P0**：接入真实 Agent 数据——3D 决策桌与合肥地图、三镜头、决策流程主干、左侧冻结 Context、右侧决策面板、底部资源栏、企业核验与一次反提案。
- **P1**：把静态文案升级为真实结构化输出——四部门初审、联席共识/分歧/少数意见/多方案、核验问题与企业披露、条件单/反提案/承诺、fallback 状态。
- **P2**：补齐最有辨识度的可视化——玩家/审计截止日视图、证据抽屉与过滤原因、承诺账、状态变化因果链、终局双时间线与证据解封、两组评价。
- **P3**：视觉增强——更复杂场景、更多企业代表动作、长过场、装饰性粒子/景深/辉光、非决策性装饰。

---

## 12. 交付验收

- 用户不读说明也能看懂当前阶段与唯一主操作；
- 三家企业在席位、地图、面板中的选中状态始终一致；
- 四部门分歧一屏可理解，完整证据按需展开；
- 用户只能选一个核验问题，企业只反提案一次；
- 原条件、反提案、最终承诺差异清晰；
- 玩家模式不泄露未来材料；审计模式能说明证据为何被拒；
- 数值变化能追溯至政府动作、企业意图、规则和证据；
- 评价不用单一总分替代过程评价和历史校准；
- 前端不自行计算财政、Agent 立场、企业回应、状态变化或评分。
