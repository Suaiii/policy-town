# 验证闭环：双政策包对照方案 v1

## 核心定义

当前产品中，玩家的唯一决策是选择一个政策包。因此，关键动作消融不再拆成资金、土地、融资等多次实验，而是仅仅比较两个完整政策包：

- **历史相似包**：在资金组织、产业配套、融资支持和实施时序上更接近真实政府动作；
- **替代政策包**：在同一决策信息下形成、但关键支持组合不同的可执行方案。

“历史相似”标签必须在结算后解封。决策前只能显示两个中性方案名称和具体条款，防止把历史答案直接提示给玩家或 Agent。

## 实验方法

两个政策包从同一个未结算状态分叉，并固定以下变量：

1. 企业及其初始状态；
2. 信息截止日与四部门可见证据；
3. 企业回应；
4. 外部历史事件；
5. 随机种子；
6. 规则引擎版本。

唯一变化项是 `proposal_id`。两条分支均由同一个确定性规则引擎结算，且对照分支不得写回玩家的正式世界线。

## 展示顺序

1. 四部门研判并形成关键核验问题；
2. 企业回应；
3. 系统编译两个政策包，玩家仅仅选择其中一个；
4. 正式世界线完成校验和结算；
5. 后台用另一个政策包从相同状态结算一次对照分支；
6. 同屏展示两条路径的项目进度、财务健康、技术成熟度、现金流和财政余额；
7. 最后解封真实政府动作，说明哪个政策包更接近历史事实；
8. 用已经完成的历史路径复现结果，判断历史相似包是否也更接近现实里程碑。

## 能证明与不能证明的内容

双政策包对照能够证明：政策选择不是装饰变量；不同政策组合进入后端以后，会通过可追踪规则产生不同结果。

它不能单独证明规则就是真实世界。有效性的完整证据由两部分共同组成：

> 历史路径复现证明规则对现实路径有解释力；双政策包对照证明结果对政府决策具有方向敏感性。

## 后端接口

- 预览政策包：`GET /api/runs/{run_id}/stages/{stage_id}/companies/{company_id}/deliberation`
- 玩家正式选择：`POST /api/runs/{run_id}/select-proposal`
- 双包受控对照：`POST /api/runs/{run_id}/compare-proposals`

对照接口返回固定变量、唯一自变量、两个分支结果、差值和解释边界。前端不需要提交任何底层参数。
正式选择接口的结算响应也会携带 `policy_package_comparison`，所以演示中不需要增加玩家操作；结算页直接展示正式世界线和另一政策包的受控分支，并在 `historical_alignment` 中事后解封历史相似关系。
