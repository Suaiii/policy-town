# 合肥产业投资推演系统：MVP 数据抓取清单

## 1. 抓取目标

MVP 数据不是为了建一个无所不包的经济数据库，而是要让六个企业原型在同一套推演引擎中真正运行。每类数据至少要回答以下一个问题：

1. 企业在决策时拥有什么基础；
2. 企业向政府要多少钱，钱会用到哪里；
3. 产品与行业环境会怎样奖励或惩罚企业；
4. 政策与事件改变了哪些具体变量；
5. 真实历史最后发生了什么，能否用于盲测校准。

数据包分为五层：城市/财政、企业/项目、产品/市场、政策、历史与自然事件。你目前提出的产品端、政策端和历史事件端是决定企业自由生长的三类动态数据；为了形成财政竞争闭环，还必须补城市财政与企业项目数据。

## 3. 产品端具体抓什么

“产品端”不能仅仅抓产品名称或行业规模。对推演真正有用的是产品经济性、供需、技术路线和企业兑现能力。

### 3.1 六个原型对应的 MVP 产品数据

| 原型 | 必抓产品数据 | 最小时间点 | 主要影响变量 | 推荐来源 |
|---|---|---|---|---|
| 大型显示制造 | LCD 面板价格或价格方向、全球/国内出货与需求、产能扩张、代际变化、国内电视/家电需求 | 2007/2008 决策前、2009 冲击、量产阶段 | `market_cycle`、`product_price_trend`、`supply_pressure`、客户协同 | 工信部电子信息资料、海关/统计局、公司公告年报、显示行业权威资料 |
| 半导体存储 | DRAM 价格方向、全球供需、制程/代际、主要厂商集中度、设备材料进口依赖、下游需求 | 2014 政策前、2016 决策点、后续关键里程碑 | 技术成熟、研发成本、市场周期、供应链风险 | 工信部/发改委、公司及项目公开材料、半导体行业协会/权威资料 |
| 高端装备技术 | 等离子/特种装备目标产品需求、关键技术成熟度、认证/样机/订单、替代技术 | 项目决策前 + 商业化节点 | 技术成熟、订单强度、规模化概率 | 公司资料、科研/专利旁证、用户企业公告、行业协会 |
| 光伏制造 | 多晶硅/硅片/组件价格方向、全球装机需求、行业产能扩张、库存、贸易政策、融资环境 | 扩产前、价格反转、债务节点 | 价格、供给压力、现金流、出口依赖 | 行业协会、能源局、海关、上市公司年报/公告、政策文件 |
| 重型装备 | 船舶/海工/大型柴油机订单、运价或新船价格方向、全球订单量、钢材价格、造船周期 | 投资前、金融危机后、交付阶段 | 订单、需求冲击、重资产沉淀、建设周期 | 工信部船舶行业资料、海关、企业/客户公告、行业协会 |
| 生物医药 | 目标产品/产线、临床或审批阶段、GMP/注册进度、预计市场、建设与投产进度 | 项目签约前、审批/建设节点 | 技术与监管里程碑、执行能力、现金消耗 | 国家药监局、药审中心、企业公告、地方项目公示 |

### 3.2 每个产品序列的最小字段

```text
industry_id
product_id
date
price_or_index
demand_or_shipments
production_or_capacity
inventory_or_supply_pressure
technology_generation
key_input_cost
import_export_exposure
source_id
publication_date
value_type
confidence
```

如果早期没有统一的产能利用率，不要补一个看似精确的百分比。可以抓“实际产量 + 设计产能”自行派生，或保存为高/中/低供给压力，并保留推导说明。国家统计局自 2017 年四季度才正式发布全国工业产能利用率序列，2007—2016 需要采用各细分产业资料。

## 4. 政策端具体抓什么

### 4.1 国家级政策包

MVP 不需要抓所有政策，只抓会改变六个原型状态变量的政策。

| 政策类别 | 必抓内容 | 影响哪些变量 | MVP 示例 |
|---|---|---|---|
| 产业规划 | 支持产业、目标技术、重点工程、适用时间 | `policy_support`、市场预期、技术研发 | 信息产业“十一五”规划、电子信息产业调整和振兴规划、战略性新兴产业规划、集成电路产业推进纲要 |
| 财税政策 | 所得税、进口设备、研发费用、补贴条件 | 项目现金流、CAPEX、研发成本 | 集成电路/软件税收政策、重大技术装备相关政策 |
| 金融政策 | 信贷投向、政策性金融、产业基金、利率/准备金变化 | 融资能力、债务成本、可追加资本 | 2008—2009 货币政策变化、国家集成电路产业基金相关文件 |
| 需求侧政策 | 家电、光伏、节能、新能源等补贴或采购 | 产品需求、订单、价格 | 家电下乡、可再生能源和光伏相关政策 |
| 技术与准入 | 技术目录、核准/审批、环保能耗、药品审批 | 建设时长、技术里程碑、项目准入 | 电子信息技术改造方向、药品注册/GMP 规则 |
| 贸易政策 | 关税、反倾销、出口限制、进口管制 | 出口需求、关键设备材料、价格 | 光伏贸易摩擦、关键设备材料政策 |

官方来源优先使用[中国政府网](https://www.gov.cn/)、[国家发展改革委](https://www.ndrc.gov.cn/)、[工业和信息化部](https://www.miit.gov.cn/)、[财政部](https://www.mof.gov.cn/)、[国家税务总局](https://www.chinatax.gov.cn/)和[科技部](https://www.most.gov.cn/)。例如，2009 年电子信息产业技术改造通知明确了项目组织和投资方向；2014 年集成电路产业推进纲要明确了产业链、金融和关键芯片支持方向。

### 4.2 安徽与合肥政策包

| 数据 | 必抓字段 | 进入模型的作用 |
|---|---|---|
| 城市/省级产业规划 | 发布时间、目标产业、规划期、重点园区和项目 | 本地产业适配、政策窗口 |
| 项目投资协议公开信息 | 签约日、总投资、政府主体、企业主体、出资/持股、附带条件 | 财政请求与历史动作基线 |
| 产业基金与国资动作 | 基金设立时间、规模、投向、增资、股权转让/退出 | 财政点数、退出回收 |
| 土地/厂房/基础设施支持 | 建设主体、到位时间、适用项目、可量化规模 | 建设进度、CAPEX 和落地速度 |
| 人才与科研平台 | 高校学科、研究院/实验室、政策生效时间 | 人才供给和技术协同 |
| 招商与供应链引入 | 上下游企业、落地日期、产品环节 | 产业链完整度与后续协同 |

### 4.3 政策文件结构化字段

```text
policy_id
title
issuer_level
issuer
publication_date
effective_date
expiry_date
target_industries
eligible_entities
tool_type
tool_value_or_strength
affected_variables
conditions
source_url
```

政策不能直接写成“企业成功 +10”。例如产业基金只能降低融资缺口或增加可获得资本，家电补贴只能改变下游需求，进口设备优惠只能降低对应 CAPEX。

## 5. 历史事件与自然事件具体抓什么

### 5.1 事件类型

| 事件类型 | MVP 事件 | 必抓字段 | 影响变量 | 主要来源 |
|---|---|---|---|---|
| 宏观危机 | 2008 国际金融危机 | 开始/缓解日期、GDP/工业/出口方向、信贷环境 | 需求、出口、融资、价格 | 国家统计局、人民银行、海关、国务院 |
| 产业周期 | LCD/光伏/船舶/存储价格与产能周期 | 起止时间、价格变化、需求变化、产能变化 | 产品价格、供给压力、订单 | 行业主管部门、协会、公司年报 |
| 技术事件 | 技术代际更替、关键工艺突破/失败 | 公开日期、替代对象、成熟度、适用企业 | 技术价值、设备重置、研发进度 | 工信部、科技部、企业公告、专业资料 |
| 贸易事件 | 反倾销、关税、出口/进口限制 | 宣布/生效日、国家地区、产品范围、税率/限制 | 出口需求、原料设备、成本 | 商务部、海关、WTO/他国主管机构 |
| 金融事件 | 利率、准备金、信用收紧/扩张 | 公布/生效日、变化幅度、适用机构 | 债务成本、融资能力 | 人民银行 |
| 自然灾害 | 洪水、地震、雪灾、高温等与项目地区/供应链相关事件 | 地点、起止、灾害等级、停运/损失、受影响行业 | 建设、物流、能源和人员 | 应急管理部、气象局、地震台网、地方通报 |
| 公共卫生 | 疫情及管控 | 地区、起止、风险等级、停工/物流/需求影响 | 开工率、物流、需求、人员 | 国家卫健委、地方卫健委、国务院联防联控 |

2007—2016 主线中疫情不是必需事件，因为新冠超出主时间窗口。它可以作为事件引擎的扩展验证，但不能为了展示“事件很多”而混入历史 Replay。2008 金融危机则是 P0，因为它直接影响显示、船舶、出口和融资环境。国家统计局的 2008 年公报和经济监测材料可以提供宏观冲击与时点依据；自然灾害优先从[应急管理部统计数据](https://www.mem.gov.cn/gk/tjsj/index.shtml)获取，疫情数据优先从[国家卫健委](https://www.nhc.gov.cn/)获取。

### 5.2 统一事件结构

```json
{
  "event_id": "MACRO-2008-GFC",
  "type": "macro_crisis",
  "announced_at": "2008-09-15",
  "effective_from": "2008-09-15",
  "effective_to": "2009-12-31",
  "regions": ["global", "china"],
  "industries": ["display", "shipbuilding", "photovoltaic"],
  "shocks": [
    {"variable": "external_demand", "direction": "down", "strength": 0.8},
    {"variable": "financing_access", "direction": "down", "strength": 0.5}
  ],
  "source_ids": ["NBS-2008-COMMUNIQUE"],
  "confidence": 0.9
}
```

事件强度可以是经过规则映射的 0—1 值，但必须同时保存原始观测和映射方法。

## 6. 六个企业原型的最小抓取包

每个原型做一张表，以下字段全部填完才能进入 MVP 候选池。

| 模块 | 每个企业必须拥有的数据 |
|---|---|
| 身份与时点 | `case_id`、匿名名称、真实原型、决策截止日、信息截止日 |
| 决策前企业 | 最近一期营收/利润/现金/负债、融资能力、研发/技术、客户/订单、管理与既往执行 |
| 拟建项目 | 总投资、政府资金请求、企业自筹、银行贷款、建设期、计划产能、关键里程碑 |
| 产品市场 | 决策前价格/需求/产能或供给压力、技术代际、关键原料/设备、进口出口暴露 |
| 城市匹配 | 合肥已有客户/产业、人才科研、基础设施、供应链缺口 |
| 政策 Context | 截止日前有效的国家、安徽、合肥政策及对应变量 |
| 事件敏感性 | 该企业受哪些价格、需求、信贷、贸易、灾害事件影响，方向与强弱 |
| 企业动作 | 在不同资金水平下可选的扩建、研发、融资、收缩、迁移、等待动作 |
| 历史政府动作 | 实际首投、追加、配套、产业链引入、重组/退出的时点与规模 |
| withheld 结果 | 开工、投产、产能/营收方向、债务/停滞、后续追加、产业链结果 |

### 6.1 每个原型的最小数据量

为了控制 10 小时工作量，每个原型先抓：

- 10—15 个决策前核心数值或可信分档；
- 3 个产品/行业时间点；
- 3—5 份关键政策；
- 3—5 个项目里程碑；
- 1 条实际政府决策序列；
- 3—4 个 withheld 校准目标；
- 每项数据的来源、发布日期和质量等级。

六个原型合计大约 180—240 条结构化事实，足以支撑 MVP；不需要先抓成千上万条新闻。

## 7. 10 小时数据抓取顺序

| 时间 | 工作 | 产出 |
|---|---|---|
| H0—H1 | 冻结字段和六个截止日；复用现有数据工程附录 | `schema`、缺口表 |
| H1—H3 | 抓六个项目的投资结构、资金请求、企业决策前状态 | 六个 `pre_cutoff` 包骨架 |
| H3—H5 | 每个行业抓 3 个产品/市场时间点 | 六条最小产品序列 |
| H5—H6.5 | 抓国家 + 合肥关键政策并映射变量 | `policy_events` |
| H6.5—H7.5 | 抓 2008 金融危机及与六案例直接相关的产业/贸易事件 | `historical_events` |
| H7.5—H9 | 抓六案例真实政府动作和 3—4 个 withheld 结果 | 六组 Replay targets |
| H9—H10 | 查发布日期、去未来泄漏、标质量与缺失 | 可运行数据包 + 审计报告 |

如果团队三人都要开发，不建议把 10 小时全部投入人工抓取。最现实的做法是从现有《数据工程附录》抽取已核验事实，优先补齐六个原型共同缺少的“决策前企业状态、政府资金结构、产品周期三点、真实动作序列”。

## 8. 数据验收规则

1. 每条事实必须有 `source_id`、来源链接/文档、`publication_date` 和 `as_of`；
2. 决策 Context 只读取 `publication_date <= cutoff_at` 的事实；
3. 截止日后材料只能进入 `withheld`，不能因其描述了早期事实就自动前移；
4. 产品价格、产能、财政等不同口径不能直接拼接，派生值必须保留公式；
5. 缺失数据允许写 `missing`，不允许由 LLM 补造；
6. 媒体材料可以补定性时间线，但关键金额、财务和持股优先用公告或官方文件；
7. 政策和事件必须映射到中间变量，不能直接修改成功率；
